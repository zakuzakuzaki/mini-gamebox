# ことばタッチ

ゲーム選択画面から起動。初期状態はカタカナで、ひらがなに切り替えても入力済みの文字は保持します。入力は20文字までで、上限では文字追加キーと「ー」の背景をグレーにして無効化し、追加入力とその読み上げを行いません。削除や決定で上限未満に戻ると再び有効になります。上限時はキーボードのすぐ上に「これいじょう にゅうりょくできません」を右詰めで表示します。表示領域を常に確保し、キー位置を動かしません。削除・文字変換は上限でも利用できます。混在入力、濁点・半濁点・小文字の切り替え、長音、1文字削除、全削除に対応します。変換できない文字は変更しません。決定すると入力欄が空になり、結果を表示したまま次の単語を入力できます。

## 構成

- `game/scenes/games/kotoba_touch/kana.gd`: 共通50音データと末尾文字の変換。
- `kotoba_touch.gd` / `.tscn`: 共通テーマを使用する画面。横画面では右から左の50音表、狭い画面では5列。50音表と補助キーは画面下端に固定し、画像・検索結果・文字種の切り替えでも位置を変えません。上部の入力・結果領域は縦スクロールせず、利用可能な高さに合わせて縮小表示します。入力欄は横スクロールして末尾を表示。
- `browser.js`: JavaScriptBridgeから呼ぶWeb Speech APIとWikipedia API。Webエクスポートに同梱。ネイティブ実行では入力のみ利用可能。
- `game/tests/test_kotoba_touch.gd` / `scripts/test-kotoba-browser.mjs`: 入力、音声呼び出し、検索、入力上限、競合、通信失敗の回帰テスト。

## 読み上げと通信

文字タッチ・変換直後と、決定直後に読み上げます。「ー」のタッチ時は直前のかなの母音を読み上げます（コー→お、ジュー→う）。連続した長音は同じ母音を使い、先頭・ン・ッの後など母音を決められない場合は「ンー」と読み上げます。入力表記は「ー」のままです。`ja-JP` / 速度0.85で、前の発話をキャンセルし、日本語音声が利用可能なら選択します。Web版ではブラウザのタッチ・マウス・キー操作イベント内でGodotの入力バッファを処理し、読み上げが次フレームに遅れて自動再生制限に阻まれることを防ぎます。ゲーム終了時は入力コールバックを解除します。端末やブラウザに日本語音声がない場合は発音を保証できませんが、入力は継続できます。端末での実音確認は別途必要です。

決定するまで通信しません。日本語Wikipediaのタイトル完全一致・リダイレクトを優先し、記事がなければひらがなをカタカナに正規化して再試行します。記事がない場合・画像がない場合・人物や作品のカテゴリに当たった場合は、ひらがな表記を引用符で囲んで検索APIで最大50記事を追加検索します。追加検索ではタイトルまたは並べ替え用の読みが一致する候補から、下記の優先順位で選びます（例：ほん→ホンには画像がないため、追加検索で本を選択）。さらに、同じ読みの「花火（曲）」のような候補がある場合は括弧部分を除いた記事名を最大5件確認し、基本の「花火」の記事も比較します。検索結果の範囲内での推定であり、すべての同音異義語を網羅するものではありません。並べ替え用の読みとの照合では濁点・半濁点を除き、小文字を通常の文字に揃えます（例：はなび／はなひ）。この表記差の吸収は検索だけに適用し、入力表示や読み上げには影響しません。

検索は15秒で打ち切り、新しい決定・クリア・画面終了で前のリクエストを中断します。世代番号でも古い応答を除外します。検索開始は1.5秒以上間隔を空け、結果を最大32語メモリに保持します。通信エラーはキャッシュせず再試行できます。ページ再読み込みでキャッシュは消え、永続保存は行いません。CORSの`origin=*`、`maxlag=5`を指定し、Cookie・リファラーは送りません。外部APIキー・バックエンドは不要です。

## 画像表示と権利

Wikipediaの`pageimages`で見つかった画像を表示します。単語や画像の事前登録は不要です。

全文検索で見つかった読みの一致する曖昧さ回避記事も最大3件たどります（例：ニク→肉→食肉）。曖昧さ回避記事ではリンク先を画像取得APIの上限に合わせて50件ずつ最大3回取得します。「カイ」のように候補が多い記事でも後半の「貝」を調べます。候補一覧を取得しきれなければ自動選択しません。

候補のWikipediaカテゴリを使い、次の順で優先します。単語や画像の対応辞書は登録しません。

1. 動物・植物・果物・野菜などの生きもの
2. 食品・料理・菓子など（酒・飲酒関連は優先しない）
3. 家具・文房具・玩具・衣類・乗り物など身近なもの
4. その他。人物・芸能・作品・企業は優先度を下げる

同じ優先度なら読みの一致、さらに記事名の短さで比較し、複数候補は優先順に最大6枚を横並びで表示します。同じ画像は重複させず、横スクロールで閲覧できます。各画像をタップすると対応するWikipediaリンク付きで拡大します。画像取得は同時2件までとし、一部が通信失敗しても取得できた画像を表示します。身近なもののカテゴリがある候補は括弧付き記事名も対象です。曖昧さ回避ページから直接リンクされる身近なものは、正式な記事名の読みが違っても候補にします（例：サカナ→魚類）。「動物」「食品」といった一般的な説明へのリンクは、入力の読みと一致しない限り候補にしません。候補一覧に直接リンクされる記事は、入力が2文字以上で記事名の先頭と一致する場合も対象です（例：ミッキー→ミッキーマウス）。通常の全文検索ではこの読みの緩和を行いません。

この優先順位はカテゴリに基づく推定で、カテゴリの不足や同音異義語によって意図と違う記事になる可能性があります。画像内容の安全性判定ではありません。通常の記事以外は採用せず、記事本文や検索スニペットは表示しません。画像内容の事前審査は行いません。

Wikipediaの画像は作者・ライセンス・利用制限のメタデータで除外しません。pageimagesには `pilicense=any` を指定し、画像の権利情報を取得する追加通信も行いません。画像はHTTPSのWikimediaホストから取得し、JPEG・PNG・WebPに対応します。通常画面は画像を大きく表示し、出典・ライセンスのボタンとクレジット表示は利用者の指定により省略しています。画像モーダルの右下には、実際に選択したWikipedia記事へのリンクを表示します。

APIの仕様は[MediaWiki PageImages](https://www.mediawiki.org/wiki/Extension:PageImages)、音声の仕様は[SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)を参照。

## 検証

`pnpm test`で既存3ゲームと新ゲーム、ブラウザ連携、Wasmローダーを検証します。ブラウザ連携テストはAPI応答を模擬し、外部ネットワークに依存しません。`pnpm build:web`と`pnpm check:web-size`で既存のCloudflare Pages向け出力を検証します。CIの公開条件・トリガーは変更していません。

実機では日本語音声を有効にし、カタカナ「ネコ」、ひらがな「ねこ」、混在「ねコ」、濁点「バナナ」、小文字・長音「ジュース」を確認してください。ネットワーク切断時の入力継続、連続決定、次の単語の入力、ゲーム選択への復帰も確認対象です。
